# Lab1 · AlgorithmAnalysis — анализ сложности алгоритмов

Учебное WPF-приложение для **эмпирического анализа временной сложности алгоритмов**: программа прогоняет выбранный алгоритм на входных данных растущего размера N, замеряет время выполнения (или число элементарных шагов), усредняет по серии запусков и строит график. Поверх измерений рисуется аппроксимация по теоретической сложности — так наглядно видно, соответствует ли реальное поведение алгоритма его асимптотической оценке O(...).

## Возможности

- 15 алгоритмов: сортировки, векторные и матричные операции, возведение в степень, поиск подстроки, расстояние Левенштейна;
- замер **времени** (мс) или **количества шагов** — в зависимости от алгоритма;
- выбор типа входных данных для сортировок: случайные / отсортированные / в обратном порядке;
- усреднение по нескольким запускам (1–20) на каждую точку;
- график «время от N» с аппроксимирующей кривой теоретической сложности;
- карточки-метрики: среднее время, теоретическая сложность, число точек;
- интерактивные подсказки на точках графика (N, значение);
- остановка длинного эксперимента без закрытия приложения.

## Как пользоваться

1. **Выберите алгоритм** в выпадающем списке «Алгоритм» — под ним появится описание, поля заполнятся безопасными значениями для этого алгоритма.
2. **Задайте параметры серии**:
   - *Максимальный размер N* — размер входных данных на последней точке графика;
   - *Шаг* — на сколько увеличивается N между точками (точек на графике — не больше 120);
   - *Запусков* — сколько раз алгоритм прогоняется на каждом N (результат усредняется).
3. Для сортировок выберите **тип входных данных** (случайные / отсортированные / в обратном порядке) — на остальных алгоритмах список неактивен.
4. Нажмите **«Построить график»**. Прогресс отображается полосой и текстом статуса; кнопка «Остановить расчёт» прерывает серию.
5. Читайте график:
   - **бирюзовая линия с точками** — измерения;
   - **коралловая линия** — аппроксимация теоретической сложностью (подогнанный по масштабу график O(...));
   - наведите курсор на точку — увидите точное значение.
6. Карточки под графиком показывают среднее время по всем точкам, теоретическую сложность и число точек.

### Примеры интересных сравнений

| Эксперимент | Что видно на графике |
|---|---|
| Bubble Sort vs Quick Sort vs Timsort, N до 2000 | квадратичный рост против N·log N |
| Polynomial Naive vs Polynomial Horner | разница между O(n²) и O(n) |
| Matrix Multiplication vs Strassen (N до 256) | выигрыш Штрассена на больших матрицах |
| Rabin-Karp vs Boyer-Moore (N до 200 000) | оба линейны, но Бойер-Мур быстрее на случайном тексте |
| Power Iterative vs Power Binary (шаги) | O(n) шагов против O(log n) |

## Алгоритмы и заявленная сложность

| Алгоритм | Сложность | Что замеряется |
|---|---|---|
| Constant Function | O(1) | время |
| Sum / Product Elements | O(n) | время |
| Polynomial Naive | O(n²) | время |
| Polynomial Horner | O(n) | время |
| Bubble Sort | O(n²) | время |
| Quick Sort | O(n log n) в среднем | время |
| Timsort (Array.Sort) | O(n log n) | время |
| Matrix Multiplication | O(n³) | время |
| Strassen Multiplication | O(n^2.81) | время |
| Power Iterative / Recursive | O(n) | шаги |
| Power Binary | O(log n) | шаги |
| Rabin-Karp | O(n + m) в среднем | время |
| Boyer-Moore | O(n) в лучшем случае, O(n·m) в худшем | время |
| Levenshtein Distance | O(n·m) | время |

## Хранение результатов

Консольная часть (`src/Core`) умеет сохранять серии измерений в SQLite (`algorithm_analysis.db`, создаётся автоматически рядом с программой) с кэшированием уже посчитанных точек. WPF-приложение выполняет эксперименты в памяти и показывает их на графике.

## Известные ограничения

- `TestConsole` в решение не входит и требует более новой версии SDK — используйте WPF-приложение.
- Точек на графике — не более 120 (иначе увеличьте шаг).
- Пределы N подобраны так, чтобы эксперимент не занимал минуты: Bubble Sort — 3000, матрицы — 256, Левенштейн — 2500, PowerRecursive — 1000, остальные — 100 000.
